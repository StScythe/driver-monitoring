# Driver Monitoring System (DMS)

[![Python 3.11](https://img.shields.io/badge/python-3.11-blue.svg)](https://www.python.org/downloads/)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![MediaPipe](https://img.shields.io/badge/MediaPipe-0.10.14-orange)](https://mediapipe.dev/)
[![OpenCV](https://img.shields.io/badge/OpenCV-4.12.0-red)](https://opencv.org/)

**Driver Monitoring System** — программная система реального времени для неинвазивного мониторинга психофизиологического состояния водителя, разработанная в рамках выпускной квалификационной работы. Система обеспечивает автоматизированную детекцию зевка, сонливости, отвлечения внимания и наклона головы на основе анализа геометрических признаков лица с использованием адаптивного порогового подхода и политопной фильтрации событий.

## 1. Функциональные возможности

### 1.1. Системы детекции

| Детектируемое состояние | Метрика | Размер политопного окна | Пороговое условие |
|:------------------------|:--------|:------------------------|:------------------|
| Зевок | MAR + Nose-Chin distance | 15 кадров (0.5 с) | MAR ≥ MAR<sub>баз</sub> × 7.26<br>Nose-Chin ≥ Nose-Chin<sub>баз</sub> × 1.38 |
| Сонливость | EAR | 60 кадров (2.0 с) | EAR < EAR<sub>баз</sub> × 0.6 |
| Отвлечение внимания | \|Yaw\| | 60 кадров (2.0 с) | \|Yaw\| ≥ 30° |
| Наклон головы | \|Roll\| | 60 кадров (2.0 с) | \|Roll\| ≥ 20° |

### 1.2. Метрика PERCLOS

PERCLOS (Percentage of Eyelid Closure) рассчитывается в скользящем окне продолжительностью 30 секунд в соответствии со стандартом ISO/TR 21926.

| Уровень усталости | Значение PERCLOS | Интерпретация |
|:------------------|-----------------:|:---------------|
| normal | < 10% | Нормальное состояние |
| light | 10% – 20% | Начальная стадия усталости |
| medium | 20% – 28% | Выраженная усталость |
| critical | ≥ 28% | Критическая усталость (требуется немедленная остановка) |

Критический уровень фиксируется при устойчивом превышении порога в течение 2 секунд.

### 1.3. Интегральная оценка критичности

На основе матрицы сочетаний событий от четырёх систем детекции определяется интегральный уровень критичности состояния водителя.

| Уровень | Код | Цветовая индикация | Условие |
|:--------|:---:|:------------------:|:--------|
| NORMAL | 0 | Зеленый | Отсутствие детектируемых событий |
| WARNING | 1 | Желтый | Зевок или отвлечение внимания |
| DANGER | 2 | Оранжевый | Сонливость или наклон головы |
| CRITICAL | 3 | Красный | PERCLOS ≥ 28% или два события одновременно |

### 2.2. Основные архитектурные решения

1. **Модульность** — каждый функциональный компонент реализован как независимый класс с чётко определённым интерфейсом, что обеспечивает возможность модификации и расширения отдельных подсистем без изменения остального кода.

2. **Локальная обработка данных** — все вычисления выполняются на стороне клиента; в базе данных сохраняются только числовые метрики и флаги событий, но не исходные изображения, что соответствует требованиям Федерального закона № 152-ФЗ «О персональных данных».

3. **Адаптивная калибровка** — система проводит 30-секундную калибровку для каждого нового водителя, вычисляя индивидуальные базовые значения геометрических признаков и адаптивные пороги.

4. **Политопная фильтрация** — решение о фиксации события принимается на основе анализа скользящего окна последовательных кадров, что позволяет эффективно отфильтровывать кратковременные ложные срабатывания.

## 3. Научное обоснование

### 3.1. Статистический анализ признаков

Статистическая значимость различий распределений геометрических признаков между классами «зевок» и «не зевок» подтверждена с использованием U-критерия Манна-Уитни (p < 0.001). Размер эффекта оценён с помощью коэффициента Cohen's d.

| Признак | U-статистика | p-value | Cohen's d | Интерпретация |
|:--------|-------------:|--------:|----------:|:---------------|
| MAR | 7 367 774 | < 0.001 | -0.997 | Большой эффект |
| Nose-Chin distance | 7 157 955 | < 0.001 | -0.940 | Большой эффект |

### 3.2. Коэффициенты адаптивного порога

| Коэффициент | Значение | Формула расчёта | Источник данных |
|:------------|---------:|:----------------|:----------------|
| K<sub>MAR</sub> | 7.26 | P25(MAR<sub>yawn</sub>) / Med(MAR<sub>no_yawn</sub>) | YawDD (n = 6998) |
| K<sub>nose_chin</sub> | 1.38 | Med(D<sub>yawn</sub>) / Med(D<sub>no_yawn</sub>) | YawDD (n = 6998) |
| K<sub>EAR</sub> | 0.6 | Фиксированный (Soukupová & Čech, 2016) | Литературные данные |

### 3.3. Сравнение покадрового и политопного методов

Эксперименты проведены на 22 видео датасета YawDD. Политопный подход обеспечивает снижение количества ложных событий по сравнению с покадровым методом.

| Метод детекции | Среднее снижение ложных событий | Медианное снижение ложных событий |
|:---------------|--------------------------------:|----------------------------------:|
| 1D-политоп (только MAR) | 28.7% | 16.7% |
| 2D-политоп (MAR + Nose-Chin) | 39.4% | 41.7% |
| Сонливость (EAR) | 94.3% | — |
| Отвлечение (\|Yaw\| > 30°) | 81.1% | — |
| Наклон головы (\|Roll\| > 20°) | 81.1% | — |

### 3.4. DEQ-эксперимент (концепция раннего предсказания)

На имитационных данных показано, что DEQ-политоп (Deep Equilibrium Model с политопной сходимостью) предсказывает достижение критического уровня PERCLOS на 27.6 секунды раньше классического PERCLOS.

| Метод | Время первого предупреждения | Опережение |
|:------|-----------------------------:|-----------:|
| PERCLOS (≥ 28%) | 76.5 с | — |
| DEQ-политоп | 48.9 с | 27.6 с |

> **Примечание:** DEQ-модуль является перспективным направлением исследований и в текущей версии MVP не реализован.

## 4. Установка и запуск

### 4.1. Требования к окружению

- Python 3.11 или выше
- USB-веб-камера (RGB)
- Операционная система: Windows 10/11, Ubuntu 20.04+, macOS 11+

### 4.2. Установка зависимостей

```bash
git clone https://github.com/StScythe/driver-monitoring.git
cd driver-monitoring

python -m venv venv
source venv/bin/activate      # Linux/macOS
# venv\Scripts\activate       # Windows

pip install -r requirements.txt
```

### **4.3. Запуск системы**

```bash
python scripts/run.py
```

### 4.4. Интерфейс управления

<pre>
======================================
СИСТЕМА МОНИТОРИНГА СОСТОЯНИЯ ВОДИТЕЛЯ
======================================

Главное меню:
1. Идентификация водителя
2. Запуск мониторинга
3. Генерация отчета
4. Выход
</pre>

**Порядок работы:**

1. Выберите пункт «Идентификация водителя» и введите идентификатор. При первом запуске система проведёт 30-секундную калибровку.
2. Выберите пункт «Запуск мониторинга». Для остановки нажмите `q` или `ESC`.
3. Выберите пункт «Генерация отчета» для получения текстовой и графической статистики.
4. Выберите пункт «Выход» для завершения работы.
